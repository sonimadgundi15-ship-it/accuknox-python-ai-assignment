2. What are the key architectural components to create an LLM chatbot?

    At a high level, an LLM chatbot has several components.
    First, we have the user interface, where the user enters a question.
    Then we have the backend or API layer. Since I have experience with Python and Django REST Framework, I understand this as the layer that receives the user's request and manages the communication between the user and the other components.
    Then we have the LLM, which understands the user's question and generates a response.
    We can use prompts or system instructions to tell the LLM how it should respond.
    We can also have conversation history or memory, which helps the chatbot understand previous messages and follow-up questions.
    If the chatbot needs to answer questions from company documents, we can use RAG, which means Retrieval-Augmented Generation.
    In RAG, documents are divided into smaller pieces and converted into embeddings. These embeddings are stored in a vector database.
    When the user asks a question, the question is also converted into an embedding. The system searches the vector database and retrieves the most relevant information.
    That information is then given to the LLM as context, and the LLM generates the final answer.
    We can also connect external tools or APIs if the chatbot needs to perform specific tasks.
    So the simple flow is:
        User → UI → Backend/API → Prompt + Memory → LLM → Response

    For RAG:
        Documents → Embeddings → Vector Database → Relevant Context → LLM → Response

    Other important components can include authentication, error handling, logging, monitoring, and security.

3. Explain vector databases

    A vector database is used to store and search vector embeddings.
    For example, suppose we have many company documents and want to create a chatbot that can answer questions from those documents.
    First, we convert the document text into embeddings. Embeddings are numerical representations of the meaning of the text.
    We store these embeddings in a vector database.
    When a user asks a question, the question is also converted into an embedding.
    The vector database then searches for the most similar or relevant information from the stored embeddings.
    That relevant information is given to the LLM as context, and the LLM generates the final answer.
    The basic flow is:
        Documents → Embeddings → Vector Database → Similarity Search → Relevant Context → LLM → Answer
